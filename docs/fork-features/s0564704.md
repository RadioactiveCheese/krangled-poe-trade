## What it does (user-facing)

The map check already lets you tag each map mod per profile as deadly, warning or good. The fork turns those tags into an **in-game stash tab search string** that highlights the maps you can run:

1. **Stash tab search generator** (Settings → Map check, a collapsible section under the mod list).
   - Toggles: *Exclude* deadly (☠) and/or warning (⚠) mods, *Require* good (✓) mods.
   - Minimum thresholds: Item Quantity, Item Rarity, Pack Size, Quality (blank means unused).
   - *Extra terms*: free text appended as-is (for example `"t16"` or `!corrupted`).
   - Output: a read-only box with the generated string, an `N/250` counter that turns red when over the limit, **Copy** and **Search stash** buttons. *Search stash* uses the existing `stash-search` action: focus the game, Ctrl+F, paste, Enter.
   - A per-mod breakdown lists each tagged mod with the short token chosen for it. Mods that did not fit are struck through.
   - Warnings: "N mod(s) left out, the search field is full" and "N mod(s) cannot be told apart from a similar mod".
   - The header row stays visible when the section is collapsed. It shows the profile name, a warning icon and the length counter.
2. **Named profiles** replace the fixed I / II / III profiles.
   - In settings, the profile bar has buttons for each profile, an inline name input for the active one, and **+** (add), **clone** (copies the active profile's tags and search settings) and **delete**. Delete needs a second click to confirm, and the last profile can't be deleted.
   - Each profile has its own search settings (toggles, thresholds, extra terms), so switching profile switches the whole search.
   - The overlay header shows profile names instead of Roman numerals. Names wrap and are truncated at 7rem.
3. **Overlay search bar.** When you check a map in the overlay, a new strip under the header has **Copy**, **Search stash**, an orange warning icon when mods were left out, and the `N/250` counter. It only appears when the active profile produces a non-empty string. You can check one map, retag a mod with a click, and run the stash search without opening settings.

Example output (deadly excluded, quantity at least 80, pack size at least 25). These tokens are illustrative, as in the mockup:

```
"ntity: \+?(8[0-9]|9[0-9]|[1-9][0-9]{2})" "ze: \+?(2[5-9]|[3-9][0-9]|[1-9][0-9]{2})" !"of elem|of phys|regenerate|less recovery"
```

## How it works

New and changed files are all in `renderer/src/web/map-check/`:

- **`map-regex.ts`**: the generator, about 400 lines.
  - `areaModIndex()` renders every `AreaMods` stat matcher with `#` replaced by `42`, grouped by stat id. It is cached per loaded language (`_indexFor !== CLIENT_STRINGS`).
  - `nonModText()` is "noise" a token must not hit. It covers the tooltip labels (quantity, rarity, pack size, more maps/scarabs/currency/div cards, area, quality, item level, rarity, corrupted, unidentified), every `AREA` name and every map base name. This stops a token like `sul` from matching "Sulphur Vents".
  - `shortestToken()` looks for the shortest lowercase substring of 3 or more characters that doesn't span a `#` roll and that appears in no other mod's text or the noise. It tries word-aligned candidates first, since those read better, then any substring, then an `^`/`$`-anchored regex built from the matcher with `#` turned into `[0-9.]+`. If nothing is unique, it falls back to the whole `^...$` line, marked `ambiguous`.
  - `atLeastPattern(min)` builds a numeric "≥ min" alternation (85 becomes `(8[5-9]|9[0-9]|[1-9][0-9]{2})`). `thresholdTerm()` puts the shortest unique tail of the label in front of it (`"ntity: \+?…"`).
  - `assemble()` builds the string from threshold terms, then `!"tokA|tokB|…"` for excluded mods, then one `"tok"` per required mod, then the extra terms.
  - `generateWith()` drops the longest tokens first until the string fits in `SEARCH_LENGTH_LIMIT = 250`. `generateMapRegex()` runs it word-aligned first. If anything was dropped, it retries with compact tokens and keeps whichever version drops fewer mods.
- **`common.ts`**:
  - Adds `MapRegexConfig`, `MapCheckProfile { name, regex }`, `MapCheckConfig.profiles[]` and `regexExpanded`.
  - Adds the helpers `activeProfile`, `decisionAt`, `setDecision`, `addProfile`, `duplicateProfile`, `removeProfile` and `defaultProfileName`.
  - The decision string (one char per profile) is no longer padded to `---`. Trailing `-` are trimmed, and a stat is removed from `selectedStats` once no profile has a decision for it.
  - `removeProfile` splices that character out of every decision string and shifts the active index.
- **`MapRegexGenerator.vue`** is the settings section. **`MapRegexBar.vue`** is the overlay strip. **`regex-actions.ts`** holds the shared `copy()` (`navigator.clipboard`) and `searchStash()` (`CLIENT->MAIN::user-action { action: 'stash-search', text }`).
- **`MapCheck.vue`** renders the named profile buttons and `<MapRegexBar>`. **`settings-maps.vue`** gets the profile bar and the generator. `findAllAreaMods` moves from `settings-maps.vue` into `map-regex.ts`. **`MapStatButton.vue`** and **`SettingsMatcherEntry.vue`** switch to `decisionAt`/`setDecision`.
- **`Config.ts`** has two migrations: v19 adds `maps.regex`, and v20 turns it into three named profiles that each get a copy of `regex`. The v20 migration also sets `regexExpanded: true` and trims padded decisions. `WidgetItemCheck.vue` defaults change to match.
- **`app_i18n.json`** gets `map_check.regex.*` and `map_check.profile_*` strings, English only.
- There are no main-process changes. The `stash-search` user action already exists.

Data flow: you click a mod in the overlay or settings. `setDecision` updates `maps.selectedStats`, and the `computed(generateMapRegex(activeProfile.regex, selectedStats, profile))` result in both the bar and the generator re-renders. Copy writes to the clipboard. Search sends IPC to main, and `stashSearch()` in `main/src/shortcuts/text-box.ts` pastes the string into the game.

## Overlap with this repo

- **Nothing like this exists here.** `renderer/src/web/map-check/` (`MapCheck.vue`, `MapStatButton.vue`, `SettingsMatcherEntry.vue`, `common.ts`, `settings-maps.vue`) still matches upstream: three fixed profiles stored as `"d--"`-style strings, no regex or search output.
- **Reusable as-is:**
  - The `stash-search` IPC action (`main/src/shortcuts/Shortcuts.ts` → `text-box.ts#stashSearch`), which `item-check/hotkeyable-actions.ts#findSimilarItems` already uses.
  - The `StashSearchWidget` and its saved-search hotkeys (`renderer/src/web/stash-search/`), which only hold static user-written strings. A generated map search could later be offered there too.
  - `STATS_ITERATOR('AreaMods')`, `ITEMS_ITERATOR` and `CLIENT_STRINGS.MAP_ITEM_QUANTITY / _RARITY / _MONSTER_PACK_SIZE / MAP_MORE_*` are all present in `renderer/src/assets/data`.
- **Differences to reconcile:**
  - This repo is at `configVersion: 23` and already uses 19–23 for other migrations. The fork's v19/v20 steps would become v24 (one merged step).
  - `_$.MAP_AREA` is used by `nonModText()` but **does not exist** in this repo's `TranslationDict`, which only has `SCRYING_MAP_AREA`. Ported verbatim, it would crash on `undefined.toLowerCase()`. Use `SCRYING_MAP_AREA` or drop it.
  - This repo has theme tokens (`surface`, `border.subtle`, `--theme-*`) in `tailwind.config`. The fork uses raw `gray-*`/`red-*` classes, which work but bypass theming.
  - This repo also has chart strings (`CHART_SHAPE/SULPHUR/GOLD`) that may appear on map tooltips. They should probably join the noise list.

4. Add tests. The fork adds none. `atLeastPattern`, `shortestToken` uniqueness, length-limit eviction and `removeProfile` index shifting are all pure functions and easy to unit-test. The set is game data that changes each league.

Rough size: about 700 changed lines from the fork, plus tests and the migration. Expect 1–2 focused days.

## Risks

- **Game-data drift:** tokens are derived at runtime, which is good, but a mod reworded in a new league can make a token stop being unique. The UI warns about ambiguity but not about tokens that collide with unindexed text (unique map names, Originator/Nightmare map lines, implicit "Delirium" or "Memory" text). False positives in the highlight are silent.
- **Search syntax assumptions:** the 250-character limit, case-insensitive substring matching, `!"a|b"` negation and regex anchors all depend on PoE 1's stash search engine and aren't checked anywhere. `^`/`$` anchoring per mod line, and `\+?` on property lines, should be verified in game.
- **Config migration:** it rewrites `selectedStats` decision strings and removes `maps.regex`. A bug here loses users' mod tags. Moving to a variable number of profiles also changes the meaning of the positional decision string, since deleting a profile shifts every later profile's tags.
- **Performance:** `shortestToken` tests every candidate substring against every other mod sample, a few hundred strings. It recomputes on each decision change for every tagged mod, in both the overlay and settings. That's fine for 10–30 tagged mods but worth memoising per (matcher, language).
- **Clipboard and focus:** *Search stash* borrows and restores the clipboard, so it isn't the same as *Copy*. `navigator.clipboard.writeText` can fail silently when the overlay isn't focused. The fork swallows that error and gives no feedback.
- **Localisation:** token derivation is language-agnostic by design. The new UI strings are English only, and languages without spaces fall back to compact tokens, which haven't been tested.
